# Lexicon: `com.foto-log.photo`

Each photo on a fotolog is a `com.foto-log.photo` record in the poster's own ATProto repo (on their PDS). The schema is in [`lexicons/com/foto-log/photo.json`](../lexicons/com/foto-log/photo.json).

## Record key

The record key is the **upload date** in the poster's time zone plus a **two-digit sequence number** for that day: `YYYY-MM-DD-NN`, with `NN` from `01` to `99`. For example, `at://did:plc:…/com.foto-log.photo/2026-10-06-01`.

For now every account may post one photo a day, so the sequence is always `01`. The key format allows more photos per day later. **The daily limit is enforced by the app, not by the key.** Before posting, the app checks which sequence numbers already exist for that date and compares the count to the account's limit (default 1). With a limit of 1, a single `getRecord` for `YYYY-MM-DD-01` is enough. A higher limit (for example, a paid tier) takes the next free number (`nextPhotoRecordKey`).

The lexicon declares the key type as `any`, so the key format is checked in code (`parsePhotoRecordKey`, `assertValidPhotoRecord`). `00`, one-digit and three-digit sequences are rejected.

## Fields

| Field | Required | Notes |
|---|---|---|
| `post` | yes | `com.atproto.repo.strongRef` to the `app.bsky.feed.post` that shares the photo. Replies to that post are the photo's guestbook. |
| `image` | yes | Blob, `image/*`, at most 1,000,000 bytes. |
| `alt` | no | Alt text, up to 1000 graphemes. |
| `aspectRatio` | no | `{ width, height }`, both integers ≥ 1. |
| `caption` | no | Up to 300 graphemes (and 3000 bytes), the same as a Bluesky post. |
| `uploadDate` | yes | `YYYY-MM-DD`, the day the photo was posted, in `timeZone`. The record key starts with it. |
| `displayDate` | yes | `YYYY-MM-DD`, the day the photo is shown under. **Always equals `uploadDate` in v1.** Letting users choose it is deferred. |
| `timeZone` | yes | IANA time zone name, e.g. `America/New_York`. |
| `createdAt` | yes | ATProto datetime (with a time zone offset). |

## Code

- `lib/photo-record.ts`:
  - `buildPhotoRecord()` builds a record and its key (sequence 1 unless given) from a `Date` and an IANA time zone, then validates it.
  - `photoRecordKey()`, `parsePhotoRecordKey()` and `nextPhotoRecordKey()` build, parse, and pick the next free key for a day under a daily limit.
  - `assertValidPhotoRecord()` validates a record read from a repo. On top of the lexicon checks, it requires real calendar dates, a known time zone, an image blob within the type and size limits (the lexicon validator doesn't enforce those), a key of the form `<uploadDate>-NN`, and the v1 rule that `displayDate` equals `uploadDate`.
- `lib/lexicon/` is generated by `npm run lex:gen` from everything in `lexicons/`. Don't edit it by hand; CI fails if it's out of date. The `com.atproto.repo.*` lexicons are copied from [bluesky-social/atproto](https://github.com/bluesky-social/atproto/tree/main/lexicons/com/atproto/repo) because the generated client refers to them.

## Changing the schema

ATProto lexicons have to stay backward compatible once records exist: no new required fields, no removed fields, and no tightened constraints. New fields must be optional.

## Publishing

The lexicon isn't published for automatic resolution yet. That needs a foto-log account DID to hold the schema record and a `_lexicon.foto-log.com` TXT record. Tracked in a follow-up issue.

# Lexicon: `com.foto-log.profile`

Images a member uploads to customize their fotolog page live in a `com.foto-log.profile` record in their own repo, so they survive without foto-log.com. The record also keeps the blobs referenced, so the PDS doesn't garbage-collect them. The schema is in [`lexicons/com/foto-log/profile.json`](../lexicons/com/foto-log/profile.json).

## Record key

`self`: one record per member.

## Fields

| Field | Required | Notes |
|---|---|---|
| `titleImage` | no | `#image`. Shown across the top of the member page in place of the text title. |
| `wallpaper` | no | `#image`. Fills the page around the member page. |
| `wallpaperMode` | no | `tile` (repeat at natural size) or `fill` (cover the window). Anything else reads as `tile`. |
| `avatar` | no | `#image`. The member's profile photo on foto-log.com, in place of their Bluesky avatar. |
| `updatedAt` | yes | ATProto datetime. |

`#image` is `{ image, aspectRatio? }`: an `image/*` blob of at most 1,000,000 bytes, and its width and height (`com.foto-log.photo#aspectRatio`). A missing field means the member hasn't set that image; removing an image deletes its field.

## Code

- `lib/member-profile.ts`: `memberImagesFromRecord()` turns a record into the images to show, treating anything invalid as unset.
- `lib/member-profile-server.ts`:
  - `getMemberImages()` reads the record from the member's PDS, cached for a minute.
  - `setMemberImage()` uploads a blob and sets one field, or clears it, and/or sets `wallpaperMode`. It keeps the other fields and uses `swapRecord` so concurrent changes don't overwrite each other.
- Images are served from the Bluesky CDN, like photos (`memberImageUrl`).
- Writing the record needs the `repo:com.foto-log.profile` OAuth scope. Members who signed in before it was added are asked to sign in again.
